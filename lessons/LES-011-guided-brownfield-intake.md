# Lesson: Brownfield work needs a guided project intake before normal cycles

## Observation / evidence

Task-level Understanding and evidenced-gap checks can work correctly while an agent still lacks the project-level frame needed to judge what matters, which system qualities deserve attention, or whether the next requested change is the most important current risk.

Brownfield projects also contain consequential historical decisions, tolerated problems, implicit success measures, external commitments, and tacit human knowledge that are not reliably recoverable from code alone. Requiring a new human collaborator to first learn the full Spiral methodology creates unnecessary adoption cost.

## Lesson

Before the first normal Spiral cycle in an existing project, conduct a short human-AI intake conversation that establishes the project's purpose, desired outcomes, important measures, consequential prior decisions, important constraints, known/tolerated risks, useful feedback sources, and relevant future direction.

Use reusable risk-discovery and metric profiles as optional suggestion sources. Make their adoption/exclusion explicit, but treat them as prompts rather than project truth. After the frame is confirmed, investigate actual project reality and present evidence-grounded candidate risks, metric gaps, missing measurements, and uncertainties to the human for prioritization and correction.

The intake should function as progressive onboarding: explain why each question matters when asking it, provide common answer options where useful, and keep custom/unknown/not-relevant answers first-class. The human should not need to understand Spiral's internal model before using it.

## Scope

Initial adoption of Spiral Developer in brownfield projects, and later re-intake when project purpose, constraints, commitments, or operating posture have materially changed.

## Confidence / limits

High confidence that project-level framing is distinct from per-change intent confirmation. Low confidence that we yet know the right fixed question set, profile taxonomy, or maturity model. Preserve nuance and gather dogfooding evidence before adding stronger structure.

## Proposed consequence

Add a mandatory-but-conversational brownfield intake step, reuse project context to persist durable answers, add a dedicated intake prompt, provide a small set of plain-Markdown starter risk-discovery/metric profiles, and make AI reality assessment plus human risk prioritization the bridge into the first normal cycle.
