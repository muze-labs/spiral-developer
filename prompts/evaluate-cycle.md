# Evaluate Cycle Prompt

Evaluate the current Spiral Developer cycle.

Do not score generic maturity.

Determine:

- For consequential direct human input, did we confirm a concrete Understanding **and evidenced gap** before product modification, and did the gap check establish effective behavior rather than merely search for related code?
- Did intended users provide meaningful feedback where product intent was uncertain?
- Where intent interpretation was material, is source evidence distinguishable from the understanding derived from it?
- Is missing or unavailable primary provenance explicit rather than silently reconstructed?
- Did the cycle reduce the nearest important uncertainty?
- Did a consequential premise in the request/design go untested because the AI simply optimized inside it?
- Would a materially different framing have changed what we built, tested, or regarded as success?
- Does each significant design element have a truthful causal reason in the causal RDF graph?
- Where requirements underdetermined a choice, did active engineering culture materially shape the selected approach, and is that influence distinguishable from hard constraints?
- Did the agent treat culture as defeasible guidance rather than an unquestionable rule?
- For revised governed implementation, are current effective causes distinct from historical lineage and transition causes?
- Did implementation history accumulate without inflating normal agent context?
- Do graph references identify the exact upstream Git versions actually used?
- Were new/changed historical references validated before becoming immutable causal commits, and did range validation ensure later removal could not hide an earlier invalid edge?
- If reachable history contains a known corrected invariant violation, is it reported honestly rather than treated as either pristine or currently unresolved?
- Does verification establish that implementation realizes design?
- Does acceptance establish that behavior satisfies the request?
- Did an upstream artifact change, and which downstream artifacts are now suspect?
- Did complexity, dependency load, or change radius grow unnecessarily?
- Did scope or abstraction boundaries expand mainly to make the model/design cleaner rather than to serve current evidence or user value?
- Did we solve deferred problems without evidence they needed to move forward?
- Which assumptions remain explicit/evidenced/inferred/unknown?
- What should the software-producing environment learn from this cycle? Is that observation important enough to record as a `LES-*` lesson?
- If there is a lesson, what is the narrowest justified scope: project practice, culture profile, or Spiral core?
- Did an earlier lesson help, create ceremony, or need refinement/supersession?
- Which bookkeeping was useful, and which was ceremonial?

Recommend only the next evidence-producing cycle, not a detailed speculative backlog.
