# Start Change Prompt

Apply Spiral Developer to this requested change.

1. Capture the current request and observable desired outcomes.
2. Identify ambiguity and the nearest important uncertainty.
3. Classify risks by horizon: blocker, near-term, deferred, existential.
4. For web interaction work, propose the fastest functioning UI/probe capable of producing meaningful intended-user feedback. Do not optimize polish unless it is needed for the feedback.
5. Record explicit non-goals and later risks that should not shape current design.
6. Draft the smallest design elements needed and connect each to request/constraint/risk.
7. Define verification and acceptance evidence before hardening implementation.
8. If legacy behavior is touched, follow the brownfield process rather than guessing intent.
9. Implement only after the causal context is sufficient for safe work.

Keep artifacts minimal. Do not create a template file unless it will be used.
